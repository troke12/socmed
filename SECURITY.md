# Security

## What's safe to commit

- All source code in `app/`, `worker/`, `scripts/`
- `.env.example` (placeholders only, no real values)
- `compose.yml`, `Caddyfile`, Dockerfiles
- Documentation (`README.md`, `SECURITY.md`, plan files)

## What must NEVER be committed

These are in `.gitignore` and are also flagged by `git` as ignored if you try to add them:

- `.env`, `.env.local`, `.env.*.local` — generated by `bash scripts/gen-master-key.sh` and contain real `SOCMED_MASTER_KEY` + `SOCMED_COOKIE_SECRET`
- `data/` — runtime SQLite DB, uploaded media, logs
- `*.pem`, `*.key` — TLS / signing keys
- `node_modules/`, `.next/`, `dist/`, `build/`
- `pnpm-lock.yaml` — fine to commit; pnpm auto-regenerates if missing

## Credential storage

All third-party API tokens are encrypted at rest with AES-256-GCM:

- Master key from `SOCMED_MASTER_KEY` env var (32 random bytes, base64)
- Per-account key derived via HKDF-SHA256(masterKey, accountId)
- Encrypted blob = `nonce(12) ‖ ciphertext ‖ authTag(16)`
- Master key never written to disk (only in `.env` which is gitignored)

Rotation: see `README.md` → "Rotating the master key" — M6.

## Reporting vulnerabilities

Open a private GitHub security advisory on the repo. Do not file public issues for security bugs.
